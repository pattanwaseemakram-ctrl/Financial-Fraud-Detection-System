01

Core Banking Fraud Interception Protocol

The Intelligence Fraud Shield runs in-line with the core banking settlement rails:

  1. Step 1: Payment Ingestion: Incoming payments arrive via REST API POST /predict.
  2. Step 2: Real-Time Feature Assembly: Preprocessing calculates 11 behavioral features including Spending_Deviation_Amount, Amount_Percent_of_Balance, and inverted location deviation.
  3. Step 3: Scaled Model Scoring: Scored against the fine-tuned Random Over-Sampling + Logistic Regression pipeline ($ROC\text{-}AUC = 0.9967$).
  4. Step 4: Calibrated Decision Cutoff ($T=0.42$): Transactions exceeding probability 0.42 are immediately blocked and flagged as Suspicious.
  5. Step 5: PostgreSQL Database Persistence: Blocked transactions are automatically written into the fraud_alerts table with a unique case ID for auditability.

03

Cost-Calibrated Decision Cutoff ($T = 0.42$)

Standard machine learning models default to a $0.50$ cutoff. In financial fraud (where fraud represents ~10% of total volume), a $0.50$ cutoff causes dangerous false negatives (missed frauds).

Standard Default ($T = 0.50$)

  • Fraud Recall: 97.00% (194/200 caught)
  • Missed Frauds: 6 missed
  • Financial Exposure: High leakage

Calibrated Optimum ($T = 0.42$)

  • Fraud Recall: 98.50% (197/200 caught)
  • Missed Frauds: Only 3 missed
  • Missed fraud rate cut by 50% with minimal false alarm increase (2.0%)
